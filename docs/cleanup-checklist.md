## 2. 정리 과정과 판단 근거

1. 브라우저·SSH·Nginx·내부/외부 통신 증거를 먼저 확보했다.
2. 루트 볼륨에 종료 시 삭제=true가 설정되어 있는지 [필터 결과](screenshots/17-delete-on-termination.png)로 확인했다.
3. EC2를 중지가 아닌 종료 처리했다. 종료됨과 연결된 블록 디바이스 없음이 표시되었다.
4. EBS 전체 목록에서 볼륨이 없음을 별도로 확인했다. 자동 삭제 설정만으로 실제 삭제 완료를 단정하지 않았다.
5. EIP 목록에 할당이 없음을 확인했다. 이번 서버는 자동 할당 퍼블릭 IP를 사용했다.
6. 서브넷 연결 해제와 서브넷·사용자 라우팅 테이블·보안 그룹 정리를 안내한 뒤, 실습자가 모두 삭제했다고 보고했다. 이 세 자원의 개별 삭제 화면은 없지만 실습 VPC 삭제 성공 화면은 확보했다.
7. IGW의 Detached 상태와 삭제 성공을 각각 확인했다.
8. 실습 VPC의 ID와 이름이 포함된 삭제 성공 알림을 확인했다.

## 3. 남아 있는 다른 자원과 확인 범위

삭제 후 화면에는 다른 VPC `vpc-02e8029e734c9df70`(172.31.0.0/16)와 IGW `igw-0d64e116e0603c044`가 보인다. 이번 실습 자원과 ID가 달라 삭제 대상으로 삼지 않았다. 이름과 주소 대역만으로 그 자원이 기본 VPC라고 확정하지 않는다.

다음은 필수 5종 정리 완료와 구분하는 추가 관리 항목이다.

- [ ] codyssey-key 키페어 및 로컬 개인 키 보관/삭제 결정: 확인 결과 미제공
- [ ] IAM 사용자·정책 보관/삭제 결정: 확인 결과 미제공
- [ ] 다른 리전 또는 서비스의 잔여 자원 확인: 별도 목록 미수집
- [ ] Billing 사용량·크레딧 최종 확인: 화면 미수집

NAT Gateway·ALB·RDS는 이번 안내 절차에서 생성하지 않았다. 계정 전체 목록을 점검했다는 의미는 아니다. AMI 원본 스냅샷을 실습자가 별도로 만든 스냅샷으로 간주하여 삭제하지 않는다.

## 4. 최종 결론

제공된 증거로 이번 평가표의 최소 5종(EC2/EBS/EIP/IGW/VPC) 정리 요건을 확인했다. 과거 사용량 또는 잔여 크레딧은 별도 결제 화면에서 확인해야 하며, 계정 전체 무과금을 이 문서에서 보증하지 않는다.
